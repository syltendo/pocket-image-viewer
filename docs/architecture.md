# Image Viewer — Core Architecture

## Decisions (locked)

- **Format:** 24-bit uncompressed Windows BMP only. `tools/bmp_convert.py`
  converts anything Pillow opens (PNG/JPG/…) into that format.
- **Navigation:** d-pad left/right steps through loaded images (wraps 0–7).
- **Scaling:** scale-to-fit into 800×720, aspect preserved, letterboxed.
- **Slots:** 8 data slots (ids 0–7). Each holds one BMP.
- **Memory:** 512 Mbit SDRAM (16-bit bus) for framebuffers. 8 × 800×720×3
  bytes = 13.8 MB < 64 MB. Fits with room to spare.

## Big picture

```
SD card ──[0082]──▶ bridge writes ──▶ slot_mgr ──▶ parser input FIFO (64KB)
                                                        │ 32-bit words
                                                        ▼
                                              bmp_parser (99 MHz)
                                                │ 800×720 RGB888, scale-to-fit
                                                ▼
                         ┌─────────────────────────────────┐
                         │ SDRAM, 64 MB                    │
                         │ 8 × framebuffer (800×720×3 B)   │
                         └─────────────────────────────────┘
                                                │ burst reads
                                                ▼
                         video_scanout ──▶ 800×720@60 ──▶ Pocket scaler
                          (99 MHz → 39.6 MHz                        (2× → 1600×1440)
                           via pixel FIFO)
```

There is no CPU. Everything is a small state machine.

## Why decode at boot, not on demand

The Pocket streams every populated data slot at boot (`[0082]` handshake,
then 32-bit bridge writes to the slot's declared address window:
`0x1n000000` for slot n, as set in `data.json`). Empty slots are
silently skipped, so boot time scales with the number of images loaded. Each slot decodes **during its stream**
straight into its own 800×720 framebuffer in SDRAM. Navigation is then just
a slot-index switch — instant, no host round-trip.

## Clocking

- `clk_74a` (74.25 MHz): APF framework, bridge, slot_mgr, navigation.
- `clk_mem` (99 MHz): SDRAM controller, BMP parser, scanout read client.
- `clk_vid` (39.6 MHz): video pixel clock (800×720@60).
- `dram_clk` (99 MHz, 340° phase-shifted): SDRAM chip clock. The phase shift
  centers the FPGA's read-data capture window (see `sdram_ctrl.v`).

Generated by `pll_imageviewer.v` (altera_pll) from `clk_74a`.

## Memory map (SDRAM, word addresses)

Each framebuffer: 800×720 pixels × 3 bytes = 1,728,000 bytes = 864,000
16-bit words. Slot n base = n × 1,152,000 words (padded for alignment).

| Word range | Contents |
|---|---|
| `n*0x119400` … `n*0x119400+0xD2F00`, n = 0..7 | Framebuffer n (864K words used of 1152K) |

Word address = {bank[1:0], row[12:0], col[9:0]}. Total used: ~13.8 MB of 64 MB.

## BMP parser (`bmp_parser.v`)

Consumes 32-bit words from the input FIFO (first file byte in `[31:24]`,
i.e. big-endian; the core sets `bridge_endian_little = 0`).

1. **Header (54 bytes):** check `BM` magic, read pixel-data offset,
   width, height (signed), planes==1, bpp==24, compression==0.
   Invalid → clear framebuffer to a dark gray (slot marked invalid).
2. **Clear:** the parser first clears the entire 800×720 framebuffer
   (letterbox background). `slot_mgr` delays the `[0082]` ACK until this
   clear finishes, so the host never streams into an unprepared slot.
3. **Geometry:** integer scale = min(800/W, 720/H) via a sequential
   divider. `dst_w`, `dst_h` centered with `x0 = (800-dst_w)/2`,
   `y0 = (720-dst_h)/2`.
4. **Pixel rows:** BMP rows are bottom-up when height > 0 (top-down when
   negative — supported). Each row padded to 4-byte boundary.
   Pixels arrive BGR; stored as RGB.
5. **Scaling:** nearest-neighbor. Source rows are expanded/contracted to
   `dst_w` via the divider; each destination row is written to SDRAM as
   1600×16-bit words (800 pixels × 2 words).

Throughput: the parser writes at ~50M words/s; a full 800×720 decode takes
~1-2 seconds depending on source size. The 64KB input FIFO absorbs the
~4 MB/s bridge stream with ample margin.

## SDRAM controller (`sdram_ctrl.v`)

99 MHz, 16-bit bus, 13 row bits / 10 col bits / 2 banks (64 MB).
Burst length 8, CAS latency 3, sequential bursts.

- **Write port:** requester streams `wr_data`/`wr_valid`; controller
  answers `wr_ready`. Bursts are only issued once all 8 words are buffered.
  Unaligned head/tail words are masked with DQM.
- **Read port:** `rd_data`/`rd_valid` with `rd_ready` backpressure. READs
  are pipelined (one every 8 clocks); a delay line generates capture
  enables for the 5-cycle read latency.
- **Refresh:** interleaved between bursts every 7.8 µs. Long transfers are
  paused for refresh, so `tREFI` is always met.
- **Arbitration:** reads have priority (video is real-time); writes use
  remaining bandwidth.

## Video pipeline (`video_scanout.v`)

- **Mode:** 800×720 @ 60 Hz. Totals 880×750 → 39.6 MHz pixel clock.
- The 99 MHz side burst-reads each 800-pixel line (1600 words) from SDRAM
  into a 4K×32 pixel FIFO. The 39.6 MHz side pops one RGB888 pixel per
  clock during the active region.
- Slot switches happen at vblank. The FIFO is pre-filled before the first
  frame to avoid underrun.
- Outputs `video_rgb`, `video_de`, `video_vs`, `video_hs` per APF convention
  (`video_skip = 0`). The Pocket scaler integer-scales 2× to 1600×1440.
- `video.json` declares the 800×720 mode.

Bandwidth: 800×720×60×3 bytes = 103.7 MB/s read. SDRAM provides ~198 MB/s
raw (99 MHz × 2 bytes); with protocol overhead, ~150 MB/s usable. Comfortable.

## Slot manager (`slot_mgr.v`)

- Watches `dataslot_requestwrite` from `core_bridge_cmd`. Delays the ACK
  until the parser signals `ready` (framebuffer cleared).
- During the transfer, routes all bridge writes to the parser input FIFO.
  The byte count from `[0082]` determines the end of the stream.
- Tracks an 8-bit `slot_valid` mask. Exposed via the `0x10xxxxxx` debug
  register along with FIFO-overflow and video-underrun sticky flags.

## Input

`cont1_key` bits 2/3 (d-pad left/right): next/previous image, edge-triggered,
wraps 0–7. The scanout switches at the next vblank.

## Known limitations / risks

- **SDRAM phase:** the 340° `dram_clk` shift is hand-calculated, not
  measured. If images show noise, this is the first thing to tune.
- **Bridge byte order:** assumes first file byte in `bridge_wr_data[31:24]`.
  Verified against APF docs but not on hardware.
- **No directory browsing:** APF has no directory-enumeration command.
  The 8-slot compromise is v1; true folder nav would need `[0190]`/`[0192]`
  tricks in v2.

## Deliberately not in v1

- **PNG/JPEG decode in RTL.** Would need a soft-CPU + software decoder.
  The converter script covers it.
- **1600×1440 native output.** 800×720 + 2× integer scale is visually
  near-identical on photos and halves every bandwidth number.
